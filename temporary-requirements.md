# Temporary Requirements: Nodes, Entities, and Edge Semantics

Status: draft

This document captures the current direction for text, entity, and graph semantics.
It is intentionally temporary and should be used to guide implementation and further design discussion.

## Core Model

- Nodes are documents.
- Entities are referents that can be mentioned inside node bodies.
- Tags are categories.
- Manual relationships between documents are "hard" edges.
- Shared-entity relationships between documents are "associative" edges.

## Semantics

### Nodes

- A node represents authored content.
- A node can be a document without being an entity.
- A node may also act as an entity page when it is the canonical place for a named thing.
- Node titles should be unique within a canvas.
- If a new node needs an autogenerated title, it can be enumerated, e.g. `Node 1`, `Node 37`.
- Title uniqueness should be enforced at create and edit time in the UI and API.
- Database-level enforcement can wait unless additional write workflows make it necessary.

### Entities

- Entities are mentioned in node bodies only.
- References should be written inline in the body text.
- A reference should resolve by exact title match first.
- If a node exists with the matching title, the entity can link to that node.
- Entity references should support inspection and navigation.
- For now, references resolve within the active canvas only.
- Matching should be exact, with lowercase canonicalization behind the scenes.

### Tags

- Tags remain category labels.
- Tags are distinct from entities.
- Tags should not be conflated with entity references.

### Edges

- Hard edges are explicit links between documents.
- Hard edges are manually created and manually removable.
- Associative edges are derived from shared entities.
- Associative edges are not manually deleted.
- Associative edges should be visually distinct from hard edges.
- Associative edges should be derived lazily for display at first.

## Graph Display

- Hard edges should render as solid lines.
- Associative edges should render as dashed or dotted lines.
- Associative edges should show why they exist on hover or click.
- The edge inspection UI should expose the shared entity or entities.

## Inspection and Browsing

- Clicking an entity should surface all nodes that mention it.
- Entity inspection should populate the right-hand panel.
- Clicking a tag should continue to show tag-related filtering and summaries.
- Clicking an entity node should link to that node when title matching resolves.
- If multiple nodes match the same title, the UI needs a disambiguation rule.
- If a full node exists for an entity, it should be treated as the primary referent.
- Other referents should appear as children under the primary referent.
- If no primary referent exists, the entity should render as a flat list of referents.

## Editing Workflow

- The app should keep edit mode and view mode separate.
- WYSIWYG editing is not the default direction.
- The body editor should remain text-first.
- The system should progressively add:
  - entity references
  - selected markdown syntax
  - richer rendering in view mode
- The first supported formatting set should be:
  - entity references
  - bold
  - italics
  - hyperlinks
- Code formatting is not part of the first pass.

## Right-Hand Panel

- The right-hand panel is expected to grow.
- Search, tags, entities, and selection-related tools likely need clearer separation.
- Tabs are a likely next step once entities are introduced.
- Candidate tabs:
  - Search
  - Tags
  - Entities
- Optional future tabs or sections may include:
  - Classes
  - node decorators
  - advanced query tools

## Remaining Open Questions

- Should entities eventually support aliases as first-class data?
- How should multi-entity disambiguation work if two nodes resolve to the same title?
- What should the first-class class/decorator model look like, if any?

## Non-Goals For Now

- No WYSIWYG editor.
- No full rich-text document model.
- No requirement that every entity must be a node.
- No requirement that every node must be an entity.
- No final decision yet on classes, aliases, or multi-entity disambiguation.
- No code formatting in the first text-formatting pass.
